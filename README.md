# NeoMarket

Учебный backend-проект маркетплейса, реализованный на Python с использованием FastAPI.

Проект был создан для практики разработки асинхронных REST API, работы с PostgreSQL, JWT-аутентификацией, взаимодействия между сервисами и написания интеграционных тестов.

> **Статус:** учебный проект / pet-project
> Проект не предназначен для использования в production.

## О проекте

NeoMarket — backend-часть учебного маркетплейса, построенная с учетом микросервисного подхода.

В рамках проекта рассматривались несколько функциональных областей:

* **B2B** — работа продавцов и управление товарами;
* **B2C** — пользовательская часть маркетплейса;
* **Moderation** — проверка и модерация товаров;
* взаимодействие сервисов через HTTP API;
* аутентификация и авторизация пользователей;
* работа с PostgreSQL в асинхронном режиме.

Архитектура и API проекта описываются с помощью OpenAPI-спецификаций, которые находятся в репозитории в файлах `neomarket-b2b.yaml`, `neomarket-b2c.yaml` и `moderation.yaml`.

## Цели проекта

Основная цель — получить практический опыт разработки backend-приложения на современном Python-стеке.

В процессе разработки были изучены и применены:

* FastAPI и асинхронные endpoint'ы;
* Pydantic для валидации данных;
* SQLAlchemy 2.x;
* асинхронная работа с PostgreSQL через `asyncpg`;
* JWT-аутентификация;
* HTTP-взаимодействие между сервисами;
* OpenAPI;
* pytest и pytest-asyncio;
* разделение приложения на отдельные функциональные модули.

## Архитектура

Проект организован вокруг нескольких доменов:

```text
                    ┌─────────────────┐
                    │     Client      │
                    └────────┬────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │    NeoMarket    │
                    │    Backend      │
                    └────────┬────────┘
                             │
              ┌──────────────┼──────────────┐
              │              │              │
              ▼              ▼              ▼
        ┌──────────┐   ┌──────────┐   ┌────────────┐
        │   B2B    │   │   B2C    │   │ Moderation │
        │  Service │   │  Service │   │  Service   │
        └────┬─────┘   └────┬─────┘   └────────────┘
             │              │
             └──────┬───────┘
                    ▼
             ┌─────────────┐
             │ PostgreSQL  │
             └─────────────┘
```

Сервисы взаимодействуют между собой через HTTP API. Для внешних запросов используется `httpx`, а работа с базой данных построена на асинхронном SQLAlchemy и `asyncpg`.

## Структура проекта

```text
neomarket/
├── app/                    # исходный код приложения
│
├── tests/                  # тесты
│
├── neomarket-b2b.yaml      # OpenAPI-описание B2B API
├── neomarket-b2c.yaml      # OpenAPI-описание B2C API
├── moderation.yaml         # OpenAPI-описание Moderation API
│
├── requirements.txt        # зависимости проекта
├── pytest.ini              # конфигурация pytest
├── conftest.py             # общие pytest fixtures
└── .gitignore
```

Конфигурация `pytest` настроена для автоматической работы с `asyncio`, что позволяет писать и запускать асинхронные тесты без дополнительной настройки каждого теста.

## Основные возможности

### Authentication

Предусмотрена JWT-аутентификация для работы с защищенными API.

Используемые библиотеки:

* `python-jose`;
* `cryptography`;
* `pydantic` / `pydantic-settings`.

### B2B

B2B-часть отвечает за сценарии, связанные с продавцами и товарами.

API описан отдельной OpenAPI-спецификацией:

```text
neomarket-b2b.yaml
```

### B2C

B2C-часть представляет пользовательскую сторону маркетплейса.

API описан в:

```text
neomarket-b2c.yaml
```

### Moderation

Отдельный API предусмотрен для сценариев модерации товаров.

Спецификация:

```text
moderation.yaml
```

### Межсервисное взаимодействие

Для коммуникации между отдельными частями системы используется HTTP.

В качестве асинхронного HTTP-клиента применяется `httpx`.

## Установка

### 1. Клонирование репозитория

```bash
git clone https://github.com/kazantsevgit/neomarket.git
cd neomarket
```

### 2. Создание виртуального окружения

Linux / macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Windows:

```bash
python -m venv .venv
.venv\Scripts\activate
```

### 3. Установка зависимостей

```bash
python -m pip install -r requirements.txt
```

Все основные runtime- и test-зависимости проекта зафиксированы в `requirements.txt`.

## Настройка

Перед запуском приложения необходимо настроить переменные окружения.

Пример:

```env
DATABASE_URL=postgresql+asyncpg://user:password@localhost:5432/neomarket

JWT_SECRET_KEY=your-secret-key
JWT_ALGORITHM=HS256
```

> Названия и набор переменных окружения необходимо сверять с текущей конфигурацией в `app`, поскольку проект является учебным и может изменяться.

## Запуск

После установки зависимостей и настройки окружения приложение можно запустить через Uvicorn.

Типичный вариант:

```bash
uvicorn app.main:app --reload
```

После запуска API будет доступно по адресу:

```text
http://127.0.0.1:8000
```

### Swagger

FastAPI автоматически предоставляет интерактивную документацию:

```text
http://127.0.0.1:8000/docs
```

### ReDoc

Альтернативная документация:

```text
http://127.0.0.1:8000/redoc
```

## Тестирование

Для тестирования используется `pytest` и `pytest-asyncio`.

Запустить все тесты:

```bash
pytest
```

Запустить тесты с подробным выводом:

```bash
pytest -v
```

Асинхронный режим pytest настроен в `pytest.ini`:

```ini
[pytest]
asyncio_mode = auto
```

## OpenAPI

В репозитории находятся спецификации API отдельных компонентов системы:

```text
neomarket-b2b.yaml
neomarket-b2c.yaml
moderation.yaml
```

Они позволяют описывать доступные endpoint'ы, request/response-модели и взаимодействие между сервисами независимо от реализации. В частности, B2B и B2C спецификации являются достаточно крупными OpenAPI-документами и занимают около 1.7 тыс. строк каждая.
